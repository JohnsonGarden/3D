# LEGO World 3D / 积木开放世界

> 把孩子亲手拼出的积木车带入一个可以驾驶、收藏、自由探索的数字世界。

**状态：交互式技术原型，已具备本机持久化车库（009）和手动 GLB 导出备份（010）。** 现在的彩色积木车是程序化占位模型；**不是**仓库中 HEIC 照片生成的数字孪生，也不是洛杉矶实景重建。

## macOS 以 root 安装失败的安全排错（008 修复）

如果本地安装弹出 `Error: Running Homebrew as root is extremely dangerous and no longer supported.`，说明进程正在以 **root** 身份运行。**不要**通过修改 Homebrew、强制管理员运行或修改系统权限来绕过。最新版两个 `.command` 入口均在任何 Homebrew/npm/下载动作前检测 root 并退出。

请在普通 Mac Terminal 执行：

```bash
id -u
whoami
```

`id -u` 应是**非 0** 的账号 UID（通常 501）；0 代表 root。如果此前开启了提权终端，使用 `exit` 返回普通账户终端，不要给 .command 或 brew 加 `sudo`，然后重新运行新版安装器。

**已有旧版本如何更新：** standalone 安装器不会覆盖 `~/BrickWorld3D` 内的旧文件。需要修复旧启动脚本，请单独下载最新 [开发分支 ZIP](https://github.com/JohnsonGarden/3D/archive/refs/heads/feat/lego-world-harness-v0.zip)，解压后运行其中的新版 `启动积木世界.command`（不要在未知权限下覆盖用户原目录）。如果 `~/BrickWorld3D` 有个人修改，请先备份；可以将最新的 `scripts/start-local.sh` 和 `scripts/require-normal-user.sh` 拷贝到原项目相应目录（保留其他文件）。

如果切回普通用户后出现 `Permission denied` / `EACCES`，可能之前使用管理员权限创建了 root 所有的安装目录：检查 `ls -ld "$HOME/BrickWorld3D"` 和 `ls -ld "$HOME/.npm"`，先确认实际归属；**不要直接递归修改整个系统或 Homebrew 的权限**。提供检查结果再选择范围最小的处理方法。

## Mac 一键本地部署（建议使用）

**适用于 MacBook Air / MacBook Pro 的 Apple Silicon 与 Intel Mac。**
本功能在 GitHub Actions 的 Linux/Chromium 环境进行自动测试；Finder 双击和 Safari 仍需在你的 Mac 上验收。

**最简方式：**下载单文件安装器 [`下载并启动积木世界.command`](下载并启动积木世界.command)，双击后自动从本仓库 GitHub 开发分支安装至 `~/BrickWorld3D`，构建并打开浏览器。重复运行会复用已有目录，不会覆盖本地修改。首次下载需要 Internet。若 ZIP 文件被系统阻止执行，按下文 Mac 安全说明操作。

**或者使用项目源码 ZIP：**

1. **下载含可运行代码的开发分支 ZIP**：[点击下载 3D 项目](https://github.com/JohnsonGarden/3D/archive/refs/heads/feat/lego-world-harness-v0.zip)。注意：目前默认 `main` 分支只有初始文件，不能用它来启动。
2. 解压 ZIP，**保留整个文件夹**。进入文件夹，双击文件 **`启动积木世界.command`**（该文件不是图片，也不需要用编辑器打开）。
3. 首次运行会检查 **Node.js >=22.12**、npm。如未安装，有 Homebrew 时脚本会**征得你同意**后安装 node@22；没有 Homebrew 则显示 Node.js 官方安装地址，安装后再次双击即可。
4. 首次安装 npm 依赖需要联网；脚本自动构建网页，然后打开默认浏览器的 **http://127.0.0.1:4173**。保留 Terminal 窗口，游戏就会持续运行。之后启动会复用现有依赖，不强制重新下载。
5. 停止：回到启动游戏的 Terminal 窗口按 **Control+C**。重新启动可以再次双击脚本。若端口上已有游戏，脚本会打开现有地址而不会杀死任何进程。

如果 macOS 阻止打开未知开发者的 `.command` 文件，先按系统提示在 **系统设置 → 隐私与安全性**中选择允许打开；只运行你从本项目仓库下载、确认来源的文件。若 ZIP 解压未保留可执行权限，或者 Finder 不能打开，可以在该项目文件夹打开 Terminal，运行：

```bash
bash scripts/start-local.sh
```

高级操作与排错：

```bash
bash scripts/start-local.sh --check       # 只检查环境，不安装/构建
bash scripts/start-local.sh --build-only  # 只安装依赖并构建
bash scripts/start-local.sh --no-open     # 启动但不弹出浏览器
BRICK_WORLD_PORT=4174 bash scripts/start-local.sh  # 本机端口 4173 被占用时
npm run test:deploy                       # 在已经构建 dist 后运行部署专项测试
```

**隐私与安全：** 绑定 `127.0.0.1`，不提供公网/局域网访问，也没有后台上传照片或音乐的 API。上传的 GLB 和音乐继续由浏览器本地读取；不创建开机自启动服务，不需要 sudo。当前示例卡车是程序化模型，真实照片重建属于后续工作；当前车库可使用浏览器 IndexedDB 保存至多 6 个 GLB，但浏览器数据清理或配额回收仍可能造成丢失。尚无 macOS 原生 `.app`、代码签名或 DMG 安装器，也尚未在用户 Mac 上验证帧率。

## 快速启动

需要 Node.js 22.12+（建议 22 LTS），npm 10+。

1. `npm install`
2. `npm run dev`，打开终端显示的本地地址。
3. `W/↑` 加速、`S/↓` 倒车、`A D/← →` 转向、`Space` 刹车、`G` 打开/关闭车库、`R` 重置。驾驶面板支持 `Q` 切换 8×4/8×8，`1`/`2`/`3` 分别切换前桥组/后桥组/中央差速锁，`T` 切换低附着路面演示。**手机/平板窄屏触控**：按住屏幕下方“油门/倒车/左转/右转/刹车”，可双指组合驾驶；松手解除输入，打开车库自动停止输入。
4. 车库里可以导入 **GLB** 模型，最多在本机浏览器保存 6 辆，支持重新选择、删除和刷新恢复；音乐由浏览器本地读取，需用户主动点击播放。

质量门禁：`npm test`、`npm run check:spec`、`npm run build`、`npm run test:e2e`（需要 Playwright 浏览器）。完整说明参见 [docs/harness.md](docs/harness.md)。

## 本机持久化车库（009）
- 打开“我的车库”并导入有效的 **GLB**（单个不超过 20MB），游戏会先校验和解析，再保存到当前浏览器的 **IndexedDB**。模型**不会上传**至任何服务器。
- 已保存车辆会在车库中显示；点击车辆名称即可再次驾驶，无需重复上传；点击“默认示例卡车”可随时切回原型车。
- 删除车辆需要二次确认；默认最多 **6 辆**。关闭浏览器后重新打开**相同地址**，上次使用的车辆可以恢复。
- **重要：不是永久备份。** 存储属于浏览器和网址来源：`http://127.0.0.1:4173` 与 `http://127.0.0.1:4174` 是两个不同的车库；`localhost` 也不是同一个来源。Safari 与 Chrome 之间不会自动共享。清理网站数据、无痕浏览或浏览器空间回收都可能删除这些模型。请保留原始 GLB 文件。
- **导出备份（010）：**打开车库，在每辆已保存的车辆旁点击 **“导出 GLB”**，浏览器会下载**与导入时逐字节一致**的原始 GLB 文件。请保存到你信任的文件夹或个人备份盘；这是手动备份，不等于整个车库的自动备份。以后在同一浏览器或另一浏览器中重新点击“导入 GLB 模型”即可恢复该车。导出不删除原车，不上传文件，也不保存 HEIC/音乐。下载行为可能受到浏览器的下载权限设置影响。
- 如果车库里的 GLB 已经损坏，导出会提示失败而不是伪造备份；请从原始文件重新导入。仍然没有跨设备自动同步、永久存储保证或 GLB 轮胎自动绑定。
- 一键安装器如果已经安装过旧版，默认会**复用旧项目文件并不会自动更新源代码**。需要新版本时，请使用 Git 更新工作分支或另外下载最新开发分支压缩包，不要在不备份的情况下覆盖自己的文件。

规格：[009 持久化车库](specs/009-persistent-garage/spec.md)。

## 真实积木的尺寸（家长实测）
车身（不含前防撞栏）10.4cm 长、3.1cm 宽、车头最高 4.7cm、轮胎直径 1.4cm。游戏选择 2.50m 的真实卡车车身宽度，按 **80.645× 等比例放大**：车身长约 8.39m，车头最高约 3.79m，轮胎直径约 1.13m。前防撞梁向前突出实测 0.8cm，对应游戏 0.645m，包含前防撞梁总长约 **9.03m**。四轴轴心中心线按车头往后：第一轴离车头 2.4cm，轴间距 3.2/1.6/1.6cm，第四轴到车尾 1.6cm；游戏中对应 1.94/4.52/5.81/7.10m（相对于车头），第一至第四轴总轴距 **5.16m**。详细规格：[006 卡车比例标定](specs/006-proportional-truck-scale/spec.md)。

## 双前轴转向与传动玩法（007，已完成可玩原型）
程序化四轴车现显示按轴位分布的 **14 条轮胎**，前两轴视觉转向、后两轴固定；车厢已移除，改为露出的低位车架与后平台。驾驶界面可切换 8×4 / 8×8、三把独立的逻辑差速锁，且在低附着路面示意条件下产生**有限的动力响应差别**，普通干燥铺装路切换模式不会无故提速。请注意这不是 Rapier 轮胎动力学或真实差速锁、悬挂仿真，导入的 GLB 模型暂不自动绑定轮胎骨骼。详见 [007 规格](specs/007-drivetrain-playable/spec.md)，[通过的 CI](https://github.com/JohnsonGarden/3D/actions/runs/39032367330)。

## 侧视校准阶段验收
家长已阶段性确认 v3 侧视示意图的**外围尺寸与整体低趴姿态**，不要求现在打磨到照片级车身细节。实测车头 4.8cm，最低底盘离地 **0.3cm**（纠正旧值 0.6cm），无货厢，14 条胎，前两轴转向；8×4/8×8 驱动切换及 3 把差速锁已完成**街机式控制与低附着示意**，尚未实现机械动力学仿真。参见 [ADR-0002](docs/adr/0002-profile-baseline.md) 和 [配置参考](src/sim/approved-profile.ts)。

## 触屏驾驶（011）
窄屏触摸设备（≤900px 的粗指针屏）会在驾驶场景下出现大号触控按钮。左侧双方向键、右侧倒车/刹车/油门，支持一根手指油门、另一根手指方向的组合操作。松手、取消触摸、浏览器切走或打开车库都会清除对应输入；**松油门会自然滑行，不会瞬间急停**。原键盘快捷键和传动系统保留。

目前通过 Chromium 移动设备仿真测试，并不表示真实 iPhone Safari、iPad Safari 已经过性能、操作舒适度和安全区域验收。该功能不涉及陀螺仪、定位权限或任何云端上传。规格见 [011 触控驾驶](specs/011-touch-driving/spec.md)。


## 建筑碰撞与停车反馈（012）
彩色城市建筑和右侧小型路边建筑采用统一的可见建筑坐标与地面碰撞矩形。驾车向右转入建筑时，简化街机碰撞会在前防撞梁进入建筑前停车，提示“碰撞：车辆已停车”，可以倒车或按 R 重置。正常沿路行驶不受影响。本次以 2.50 m 宽、9.03 m 含保险杠车长进行 **二维旋转矩形近似**，并非真实四轴刚体、轮胎接地点、上下坡、街沿或导入 GLB 的精准网格碰撞；这些属于后续物理里程碑。详见 [012 规格](specs/012-static-contact/spec.md)。


## 本机帧率诊断（013）
驾驶页顶部点击 **“性能诊断”**，即可在当前浏览器观看真实动画帧间隔滚动样本的**帧率中位数（FPS）**、**p95 帧间隔（ms）**和有效样本数。至少 30 个有效帧后开始展示，最多保留 300 帧；排除背景标签页、超过 250ms 的暂停帧。关闭后停止采样，本功能不写入本地存储，也不向云端发送数据。

**验收目标（而非已实现的跑分）：**参考桌面电脑正常驾驶时 FPS 中位数 ≥60、p95 帧间隔 ≤33ms。用户应在实际 Mac 的 Chrome/Safari 各自运行，记录系统/浏览器/屏幕大小/驾驶场景/实测数据与截图。Chromium CI 能验证功能可以显示数据，**不能**替代 Apple Silicon 实机性能测量或 GPU 绘制耗时分析。规格见 [013 帧率诊断](specs/013-frame-diagnostics/spec.md)。
